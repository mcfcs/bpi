Why the two guards

  • The judges’ password (DEMO_BASIC_AUTH): the demo sign-in lets anyone pick Ben or Ana with no password, which is what we want for judges, but not for anyone who finds the link.
  • The secret key (BACKEND_SHARED_SECRET): on Render’s free plan the backend has its own public address. The frontend adds the key to every call it forwards, and the backend refuses calls without it, so nobody can skip the password by calling the backend directly. /api/health stays open so the uptime checker can reach it.

Both live in the code already (frontend/proxy.ts and the backend’s settings) and are off unless their variables are set, so our laptops are unaffected.

Test the timeout before sending the link (step 9). Vercel forwards each /api call to Render, and its documentation doesn’t say how long it waits. Our briefs take about 11 seconds, at most 20 in testing, so this should be fine. If briefs fail through the Vercel link, move the frontend to Render (the fallback at the end).
Use only the synthetic data in the repo. Keep every key in the hosts’ environment settings, never in Git.

Before you start

  • The latest code is on GitHub (mcfcs/bpi, branch main), including frontend/proxy.ts, the backend key check and the newest migrations. Commit and push first; never commit backend/.env.local.
  • Accounts: Vercel and Render (both signed in with GitHub and allowed to read the repo), Supabase, and an uptime checker such as UptimeRobot.
  • A laptop with the repo and a working backend virtualenv (you load the database from it). Node is only needed for resetting the demo (step 10).
  • Two random strings, one for the key and one for the sign-in tokens. Make each with openssl rand -hex 32, or any long password generator.
  • About 1½ hours.

1Get an AWS access key for Bedrock

Off AWS, the backend can’t use your SSO sign-in or an IAM role, so it needs a key.

  1. AWS console (DataWave account) → IAM → Users → Create user alamkansya-render (no console access).
  2. Add an inline policy, name it bedrock-invoke:
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["bedrock:InvokeModel", "bedrock:InvokeModelWithResponseStream"],
    "Resource": "*"
  }]
}
  1. User → Security credentials → Create access key → “Application running outside AWS”. Save the key ID and secret somewhere private.
If AWS says you aren’t allowed to create users, ask the organisers for a key. Without one, use the Anthropic API instead: set LLM_PROVIDER=anthropic, ANTHROPIC_API_KEY and LLM_MODEL=claude-sonnet-5-5 in step 5, and EMBEDDING_PROVIDER=hashing in steps 4 and 5. It works on the free plan, but search is weaker (about 75% on reworded questions, against 94% on the slides), and prompts go to Anthropic rather than staying in AWS.

2Create the Supabase database

  1. supabase.com → New project, Free plan, region Southeast Asia (Singapore). Set a strong database password and save it.
  2. Project → Connect → copy the Session pooler string (port 5432). Fill in the password:
postgresql://postgres.abcdefghijkl:PASSWORD@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres

Use the session pooler, not the transaction pooler (port 6543): the app sets each user’s identity inside a database transaction and uses prepared statements, which the transaction pooler doesn’t handle well. abcdefghijkl is your project ref.

3Fill in backend/.env.supabase

The repo has a fill-in file for this, kept out of Git. Open backend/.env.supabase and set:

  • SUPABASE_DB_URL: the Session pooler string from step 2, with your password.
  • EMBEDDING_PROVIDER / EMBEDDING_MODEL: leave them as Bedrock + Cohere Embed v4 (they must match Render in step 5).
  • How this laptop reaches Bedrock: the access key from step 1 (AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY), or leave those blank to use your AWS sign-in (AWS_PROFILE).

Never commit this file or paste it in chat. It is listed in .gitignore.

4Create the tables and load the studies

From the repo folder on your laptop:

backend/.venv/Scripts/python backend/scripts/supabase_setup.py --check   # connection + search model only
backend/.venv/Scripts/python backend/scripts/supabase_setup.py           # migrations, studies, search data

It applies every file in supabase/migrations (on Supabase they run as they are: the auth schema, roles and pgvector already exist), then loads the teams, demo people, 33 approved studies, 6 reports waiting for review and the search data for all 160 findings. Expect it to end with “Embedded 160 findings with bedrock:global.cohere.embed-v4:0”. Running it again is safe. On macOS or Linux use .venv/bin/python.

6Deploy the frontend on Vercel (free)

  1. vercel.com → Add New… → Project → import mcfcs/bpi.
  2. Root Directory: frontend. Framework preset: Next.js (detected). Leave the build settings as they are.
  3. Environment Variables:
BACKEND_URL=https://alamkansya-api.onrender.com
BACKEND_SHARED_SECRET=<random string #2, the same as on Render>
DEMO_BASIC_AUTH=judges:CHOOSE-A-PASSWORD
  1. Deploy. Then Project → Settings → Functions → Function Region: Singapore (sin1), if your plan offers it, and redeploy. It puts Vercel’s forwarding next to the backend instead of in the US.

BACKEND_SHARED_SECRET must match on both sides exactly. If you change it, redeploy both.

7Check it

  1. Open the Vercel address, e.g. https://alamkansya.vercel.app. The browser asks for judges and the password.
  2. Pick Ben Santos from the persona menu and click the SME example question. A cited brief should appear.

8Keep the backend awake

Render’s free backend sleeps after about 15 idle minutes, and waking takes about a minute, long enough for a judge’s first question to fail.

  1. UptimeRobot (free) → New monitor → HTTP(s).
  2. URL https://alamkansya-api.onrender.com/api/health, every 5 minutes.

Render gives each account about 750 free hours a month, enough to keep one service awake the whole month. Vercel doesn’t sleep. Check Render’s current free-tier rules; turn the monitor off after judging.

9Test the timeout

Through the Vercel link, ask 5 or 6 different questions, including the three below and a follow-up. Every brief should finish. If any fails with an error or a timeout while the same question works when you test locally, Vercel is cutting off the forwarded call: use the fallback below.

  • “Why do SME owners drop off during online loan applications?”
  • “How do market vendors feel about accepting QR payments?”
  • “Do young professionals prefer cashback or travel rewards on credit cards?”

10Resetting the demo

Approving the Mindanao report uses up the demo. Before each judging session, from your laptop:

npx supabase login
npx supabase link --project-ref abcdefghijkl     # once; the ref is in your Supabase URL
npx supabase db reset --linked                  # wipes the database and re-applies the migrations
backend/.venv/Scripts/python backend/scripts/supabase_setup.py --seed-only

Updating after a change

Push to main: Vercel and Render redeploy on their own. If the change adds a migration, run npx supabase db push from your laptop.

Tearing it down after judging

  1. Vercel → delete the project. Render → delete the service(s). UptimeRobot → delete the monitor(s).
  2. Supabase → Project settings → Delete project.
  3. AWS → IAM → delete the access key and the user alamkansya-render.
