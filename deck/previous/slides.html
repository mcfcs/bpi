Value for customers · Problem importance

BPI has often already paid for the answer. Business units can’t find it.

Studies sit in team silos

Each study belongs to the unit that commissioned it. Another unit that could reuse it rarely knows it exists, and access is granted file by file.

Search needs the exact keywords

SharePoint matching misses a question asked in different words, and returns “hits” where the keyword appears but the topic is far off.

So business units wait on S&I

Questions existing studies already answer go to analysts instead. Two units can commission work that reaches the same answer.

Why it matters now: business units compete with fintechs on speed. A decision made without the study BPI already owns is slower, costlier, or both.

Source: the team’s S&I consultations, 21 Oct and 4 Nov 20262

Value for customers · Who it is for

Three people, one slow loop

Business-unit decision maker

Wants a quick, sound answer in plain language, often without a research background. Today: asks around, searches keywords, waits.

S&I analyst

Answers repeat questions from studies that already exist, and re-explains the same findings for each unit’s way of asking.

Study owner / approver

Decides who may read a study. Today each request is handled one at a time through Power Apps and Power Automate.

The time this loop takes “can’t be quantified” today, S&I told us. That is a finding in itself: nobody can see how many questions existing research could have answered.

Solution design · Solution logic

How a question becomes a brief

Code + DB

1 · Permissions

The query runs as the user. Row-level security returns only studies their team may read.

→
AI search

2 · Retrieve

Meaning + keyword search over findings; floors and topic checks cut off-topic hits.

→
Code

3 · Compare

Differences classified as age, region, period or a real conflict. Evidence tiers scored.

→
Claude

4 · Write

Claude writes the wording from those findings only, and picks which metrics to chart.

→
Code

5 · Check

Every claim validated: real citations, hedged qualitative claims. Failing drafts rewritten once, then dropped.

→
Code + DB

6 · Assemble

Charts and confidence from database values. Stored, audited, shown.

What the model never does

Supply a number, classify a difference, set a tier or confidence, see a restricted finding, or approve anything.

Stack

Next.js · FastAPI · Postgres with pgvector and row-level security · Claude Sonnet 5.5 and Cohere Embed v4 on Amazon Bedrock (Singapore)

Pipeline modules: retrieval → divergence → llm → validators → confidence + charts8

Responsible & effective AI use · Safeguards

Checks in code, decisions with people

AgainstSafeguard
InaccuracyNumbers, tiers and confidence from code; every claim validated; failing claims dropped
Misleading synthesisQualitative claims must be hedged; “conflict” only for same people, same period
PrivacyDatabase row-level security; restricted findings never reach the model
BiasWho, where and when shown on every figure; gaps listed; place named in the question honoured
InjectionUploads go to human review before they are searchable
Over-reliance, residencyConfidence and gaps up front; append-only audit log; model swappable, Bedrock logs off

Four human checkpoints

  1. Study review: an analyst approves every study before it is searchable
  2. Access: the owning team grants or refuses each request
  3. Ask an analyst: one click from any brief, with a drafted question
  4. Commissioning: nothing is sent until a person sends it
Enforced by tests: test_acceptance, test_permissions, test_redteam13

Feasibility & scalability · Implementation feasibility

It runs today, on tools a bank already uses

Data

Study reports as PDFs, plus a study card per report (method, sample, fieldwork, owner, access). No raw respondent data needed.

Technology

Postgres + pgvector (RDS or Aurora), a Python API, a web app. Permissions live in the database, not the AI.

AI models

Claude Sonnet 5.5 and Cohere Embed v4 on Amazon Bedrock. Prompts stay inside AWS; the model is one setting to change.

Process

Fits S&I’s existing flow: commission, review, publish, monitor. S&I keeps the approval steps it has now, in one place.

Users

Business-unit staff, S&I analysts and study owners. Plain-English copy; no training on prompts needed.
